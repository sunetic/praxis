# Chat

Chat 是 Praxis 的主要工作入口。它不是单轮问答框，而是一个能够选择数据源、调用数据库工具、使用 Skill 和知识库、处理确认动作并保存结果的任务工作区。

## 适合做什么

- 数据库健康检查、故障排查和 SQL 诊断；
- 先收集多类证据，再形成结论的复杂任务；
- 探索一套新的工作方法，稳定后保存为 Agent；
- 通过知识库对照团队规范、操作手册或事件分级标准。

## 一次可靠对话的基本方式

1. 选择正确的数据源和 Agent。
2. 说明目标、时间范围、输出要求和禁止事项。
3. 要求先收集证据，并区分事实、推断和建议。
4. 检查工具调用结果；遇到高风险确认卡时，先核对对象与影响范围。
5. 对话变得稳定且可复用后，再保存为 Agent。

## 长任务中的行为

复杂任务可能包含多轮工具调用、重试和验证。Praxis 会维护任务约束和运行证据，并在上下文接近限制时压缩较早内容。界面中的过程事件用于说明正在做什么，最终答案则应汇总已验证的结论和仍未解决的问题。

供应商限流或网络错误不等于任务质量差。若运行中断，应先重试或检查模型服务，再判断 Praxis 的规划是否存在问题。批量比较时使用 [Eval](../reliability/evaluation.md)，不要仅凭一次聊天做模型结论。

## 安全提示

默认用只读账户执行诊断。对于 SQL 写入、终止会话或平台对象删除，确认卡是安全边界的一部分；不要在没有核对实际目标时批准。
