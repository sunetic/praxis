# 长任务可靠性

长任务和复杂任务的难点不是“模型能不能写出一段好答案”，而是它能否在多轮工具调用中持续记住目标、处理失败、验证证据，并在真正完成时才结束。

Praxis 从以下几个方面增强这类任务。

## 任务约束

复杂请求会被整理为可执行目标和完成条件。后续步骤应围绕这些约束推进，避免对话变长后只完成最容易的一部分。

## 证据驱动

Agent 的结论应建立在工具结果、数据库现场或知识库材料上。运行过程中保留的证据用于检查关键子问题是否覆盖，并支持最终验证，而不是只依赖模型自评“已经完成”。

## 失败恢复

短暂的限流、连接错误和无进展循环需要区别处理：可恢复错误可以退避重试；重复无进展应停止消耗并暴露问题；高风险动作不能通过重试绕过确认。

## 上下文管理

接近模型上下文窗口时，Praxis 会压缩较早内容，同时尽量保留任务目标、关键事实、未完成项和近期交互。模型窗口和压缩阈值可在设置中调整，但任何改动都应通过长任务 Eval 验证。

## 并行与验证

互不依赖的只读调查可以并行，以减少总耗时；有状态或高风险动作仍需有序执行。任务结束前的验证关注完成条件和证据缺口，而不是答案篇幅。

这些机制提高成功概率，但不能消除模型、供应商和数据库现场的波动。版本回归与模型选择仍需使用同一套 [Eval](evaluation.md) 重复测量。
