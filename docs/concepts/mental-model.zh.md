# 核心概念

Praxis 的功能可以理解成四层。

| 层次 | 主要对象 | 作用 |
| --- | --- | --- |
| 连接 | 数据源、服务、知识库、渠道 | 接入数据库、外部控制面、领域资料和通知出口 |
| 智能 | Chat、Agent、Skill | 理解任务、调用工具、复用角色与方法 |
| 自动化 | Function、Scheduler | 把稳定流程做成可测试、可发布、可定时的能力 |
| 治理 | 能力、安全设置、运行记录、追踪、Eval | 控制边界，并判断系统是否可靠 |

## 常见工作流

### 从问题到可复用 Agent

1. 在 Chat 中选择数据源并描述目标。
2. Agent 读取数据库证据，必要时调用知识库和专业 Skill。
3. 通过多轮对话把范围、判断标准和输出形式调整稳定。
4. 保存为 Agent，后续对其他数据源重复运行，或交给 Scheduler 定时运行。

### 从探索到确定性自动化

1. 先用 Chat 探索可行步骤。
2. 当输入、输出和执行逻辑已经清晰，构建 Function。
3. 在构建工作区用代表性输入测试，确认业务结果后发布。
4. 直接运行，或配置 Scheduler 周期触发。

## Agent、Skill 与 Function 怎么选

| 需求 | 更合适的对象 |
| --- | --- |
| 需要模型根据现场信息动态决定下一步 | Agent |
| 需要给 Agent 一套领域方法、规则或参考材料 | Skill |
| 输入输出稳定，希望结果更可重复 | Function |
| 需要固定时间自动运行 Agent 或 Function | Scheduler |

这些对象不是互斥的。一个 Agent 可以使用多个 Skill 和工具，Scheduler 可以运行 Agent 或 Function。
